# Building Curtain Firmware

## Prerequisites

- Docker
- VS Code with the [Dev Containers extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) (for IDE workflow)

## Build the Docker image

```bash
./build-docker.sh
```

This builds the `curtain-firmware` image based on Ubuntu 24.04 with:
- pico-sdk 2.2.0 at `/pico-sdk`
- ARM GCC 13 toolchain (`gcc-arm-none-eabi`)
- clangd 18
- OpenOCD (Raspberry Pi fork, `sdk-2.0.0` branch)

This step takes several minutes the first time due to cloning the SDK submodules and building OpenOCD.

## Build the firmware

Start the container with the `firmware/` directory mounted:

```bash
./run-docker.sh
```

Inside the container, configure and build:

```bash
mkdir -p build && cd build
cmake ..
make -j$(nproc)
```

The build outputs land in `firmware/build/`:
- `blink.uf2` — drag-and-drop onto Pico W in BOOTSEL mode
- `blink.elf` — used for debugging via OpenOCD/picoprobe

## Flashing the Pico W

### Option 1: USB drag-and-drop (recommended)

No extra hardware needed. This is the normal way to flash during development.

1. Hold the **BOOTSEL** button on the Pico W
2. Plug in the USB cable while holding BOOTSEL (or plug in first, then hold BOOTSEL and press RUN/reset if you have one)
3. The Pico W mounts as a USB drive called `RPI-RP2`
4. Copy the UF2 file onto it — the board reboots and runs the firmware immediately

```bash
cp firmware/build/blink.uf2 /media/$USER/RPI-RP2/
```

### Option 2: picotool via USB

`picotool` is built automatically as part of the cmake build. It can flash without entering BOOTSEL mode if the running firmware has USB stdio enabled:

```bash
picotool load firmware/build/blink.uf2 --force
```

### Option 3: OpenOCD via picoprobe (SWD)

`flash.sh` uses OpenOCD with the picoprobe interface:

```bash
./flash.sh
```

**What is picoprobe?** A picoprobe is a second Raspberry Pi Pico (or Pico W) flashed with the
[picoprobe firmware](https://github.com/raspberrypi/picoprobe). It acts as a SWD debug probe,
connecting to the target Pico W via three wires:

| Picoprobe pin | Target Pico W pin |
|---------------|-------------------|
| GND           | GND               |
| GP2           | SWDIO             |
| GP3           | SWDCLK            |

This method is only needed for **live debugging** (breakpoints, stepping through code with GDB).
For simply flashing firmware, use Option 1 or 2 instead.

To use `flash.sh` from inside the Docker container, run the container with `--privileged` and the
probe's USB device passed through.

## VS Code / Dev Container (IDE workflow)

1. Build the Docker image first (`./build-docker.sh`).
2. Open the project root in VS Code.
3. When prompted, click **Reopen in Container** (or run `Dev Containers: Reopen in Container` from the command palette).
4. VS Code attaches to the container with the `firmware/` folder as the workspace.
5. Run the cmake configure + build steps above (or use the CMake Tools extension UI).
6. clangd reads `firmware/build/compile_commands.json` for accurate IntelliSense — build at least once before expecting full IDE support.

### clangd notes

- clangd is configured with `--query-driver=/usr/bin/arm-none-eabi-*` so it can discover the
  ARM toolchain's implicit include paths (newlib headers such as `cassert`, `cstdio`, etc.).
  Without this, standard library headers appear as missing.
- The `compile_commands.json` is generated by CMake (`CMAKE_EXPORT_COMPILE_COMMANDS ON`) into
  `firmware/build/`. A symlink `firmware/compile_commands.json -> build/compile_commands.json`
  is present so clangd can also find it from the source root.
- The MS C++ IntelliSense engine is disabled in `.vscode/settings.json`; clangd handles everything.
- If headers still appear missing after opening VS Code, run **Ctrl+Shift+P → "clangd: Restart
  language server"**.
